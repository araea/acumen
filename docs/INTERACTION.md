## 零、群聊不是 App

把 App 的假设逐条去掉，剩下的就是群聊这个场所的约束：

| App 里有 | QQ 群里 | 由此推出 |
| --- | --- | --- |
| 返回键、导航栈 | 没有，只有一条往下滚的时间线 | 每条消息都要自带上下文，不能依赖“上一屏” |
| 模态对话框 | 没有，追问只是又一条消息 | 追问不能单方面占住别人的下一句话 |
| 悬停、长按、右键 | 没有，只有“发一条消息” | 所有功能都要能用一行文字触达 |
| 当前页面 | 没有，上下文随时被别人的消息冲走 | 状态要能随时重新调出来 |
| 私有画布 | 没有，全体成员都被迫看见机器人的每一条输出 | 刷屏占用的是公共空间 |
| 应用内设置页 | 没有，配置在 `config.toml` 或 `/ctl` 里，一般人看不到 | 行为要能从消息本身推断，不要求先读文档 |
| 稳定的网络与后台 | 没有，进程会被 ColorOS 清理器杀掉，浏览器可能缺失 | 长任务要能中断、能重新发起，降级要安静 |

这些插件不是 App，是群聊里的一个参与者。照搬 App 的交互，做出来的东西在群里不成立。

## 一、Think Human：八条原则的译法

这套系统从 Apple HIG 取两层。一层是体验要达到的质量，九条，列在[设计系统的体验原则一节](DESIGN_SYSTEM.md#四体验原则--apple-hig)：清晰、尊重内容、层级、深度、直接、反馈、一致、渐进呈现、可达。另一层是拿不准时偏向谁，即下面这八条。

依据是 Apple HIG 的八条设计原则。左栏是原话，右栏是它在 ayjx 里的含义。

| 原则 | Apple 的一句话 | 在 ayjx 里意味着 |
| --- | --- | --- |
| Purpose 目的 | Make something meaningful. | 一个插件只做一件事；链接的准入判据是 `video_parse::is_video_link` 一处，`webshot` 与它不各截一次又取一次 |
| Agency 自主 | Let people do things their own way. | 出图能关、插件的开关与配置能改、推送目标能逐个增删、搭话能在群里关 |
| Responsibility 责任 | Act in people's best interest. | 破坏性操作有门槛，花钱的能力有额度（`music_budget`、`video_budget`、`draw_budget`），撤回失败只记日志 |
| Familiarity 熟悉 | Build on what people know. | 用群里既有的动作：@、引用、撤回、发一条消息 |
| Flexibility 弹性 | Adapt to diverse contexts and needs. | 浏览器不可用或超时，卡片退回等价的纯文本；取不到原片，回一句说清卡在哪，重贴一次就能再取 |
| Simplicity 简约 | Be clear and direct. | 一条消息至多三句，短反馈不出图，细节进卡片；该给的信息不能省 |
| Craft 工艺 | Care about every detail. | 数字两侧的空格、「@」后面那个空格补不补、`[face:277]` 会不会漏成原文、并发时那把锁 |
| Delight 愉悦 | Make it human. | 高光时刻给一次；Apple 在同一段里说 Don't mistake delight for decoration. |

最后一条与 `CONTENT.md` 的克制是同一条。Apple 的原话是：

> Keep in mind that people are trying to accomplish a task, so don't let pursuit of
> delight for its own sake get in the way of your product's core purpose.

## 二、四条硬规则

**一条消息说清一件事，超过三句就出图。** 群聊是共享的，多刷一行由所有人承担。判据是 `CONTENT.md` 3.3，出路是卡片或帮助页。

**等待要有终点。** 判据是用户怎么知道它结束了，不是机器人还在跑。定时推送有排期与 `/ai推送状态`，卡片提取有 30 天的有效期，模型请求有 `reply_timeout_seconds`，搭话有 `max_pending_seconds`。

**状态能重新调出来。** `/ai推送状态` 能问当前目标的全部参数，`/ctl list` 能问全部插件，`/help <插件>` 能问指令表。凡是「上一次它说了什么」，都要有一条指令能再问一次。

**把选项摆在眼前，不要求用户记住。** 参数占位写成 `<必填>` / `[可选]`，限流被拒时把恢复方式一起说了，帮助卡的页脚给一条能立刻执行的指令。要求用户回忆的地方都要改。

## 三、交互模式

### 1. 前缀与符号指令

指令前缀 `/` 由 `command_prefix` 配置。注册表里只写指令本体，渲染时由框架拼上；符号指令（`/#`、`##`、`~名`、`-#`、`~#`、`~=`、`-*`、`画·<预设>`）自带写法，不再拼前缀。

写进正文的指令必须带上当前前缀，且能整条抄走。硬编码 `/ctl` 在部署者改前缀后会失效（`CONTENT.md` 3.4）。

### 2. 后缀驱动的房间设置

`oai` 的房间用在被操作对象后面追加符号的方式表达，不另立指令：

```text
房间%模型        换这间房的模型
房间$<提示词>    改这间房的提示词
房间?            联网开关换一边
房间?开 / 房间?关 明确指定；房间?默认 交回全局
```

这是 ayjx 里唯一一套「对象加后缀」的语法，只在 oai 房间内成立。要加新的房间设置就沿用这套符号。

### 3. 引用即上下文

ayjx 不用「等你下一句话」这种模态。需要指定对象时，一律用引用把上下文固定住：

```text
引用一条消息 + 撤回            → 撤回它
引用一条含图的消息 + 转链接      → 提取直链
引用一张表情 + 收 / 偷 / 存表情  → 收藏它
引用资讯卡片 + 0 或 2 / 1,3-5   → 提取对应链接（无需前缀）
```

这样做的结果有三样：不占住任何人的下一句话，用户可以不回，也可以过两周再回。自带上下文，时间线被冲走不影响。失败可解释，没有引用段时能回一句「引用一条……」，不沉默。

由插件自己存对应关系的只有资讯卡片一种，留 30 天，超出就当没有这条记录。这条口径要写在用户看得到的地方：`/help` 的指令说明、以及找不到时的报错。另外三种（撤回、转链接、收藏表情）不存对应关系，引用过来的是平台上的那条消息本体，窗口由 QQ 给。

只在确有引用段、且文本形状对得上时才响应，其余一律放行。宁可漏接，不可误吞。

对形状的时候要记得正文前面可能挂着 @：QQ 的引用回复会自动补一个 @，平台又把这个 @ 的**显示名**写进正文（`at` 段后面跟着一段「@名字 正文」，`at` 段自己不带名字），而插件读的 `raw_message` 只拼文本段。于是用户只回「2」，拿到的却是「@A宝好腻害！ 2」。正文不带 @ 时只有整段一个候选，带 @ 时从名字后面逐词往后各算一截，由插件挑认得出的那一截——名字多长猜不出来，昵称里还可能带空格。资讯提取要的是「剩下一截是序号」。写在 `command::spoken_bodies`，新加引用类交互照它办。

### 4. 动作唯一的那些不需要引用

需要指定对象时才用引用。动作唯一的链接类插件不看引用段：正文或卡片里的视频站链接进来，就地取原片（`video_parse`），@、引用、指令一概不用，也没有第二步。判据不是「读起来更短」，是**没有第二个可能被指的对象**——一条消息里出现几条视频链接时，取第一条，剩下的由用户自己分开贴。

### 5. 出图与文本的分工

卡片图在群里按缩略图阅读，读者第一眼看到的是版式，不是正文。引用卡片回序号这条路径把图当目录，把文本当正文：图上放得下的信息保持排版，放不下的（链接、完整摘要）留在按需提取里。图是增强，不是前提，出图那条路要有一份等价的纯文本，见第五节。

### 6. 并发与串行化

群消息很密，实测约 1.1 万条/天，峰值 1.5 条/秒，两个人在同一毫秒发同一条指令是常态。凡是「读状态、算、写状态」的动作都要串行化；拿不到的时候回一句 ⏳ 说明情况，不静默丢弃，静默丢弃会让人以为机器人没有响应，然后重发。

出图与取片是这里的两处排队，按一类工作分闸门：`render::web::shoot`（3）、`webshot` 自己的（2）、视频解析的取片（2）。闸门在各自的超时之外获取，排在后头的请求不会因为前面那张慢而被判超时。加新的重活调用点，照这两处办。

### 7. 长任务

生成类任务（画图、写歌、拍片、翻页截图、出画像）先回一条 ⏳，再在完成时回结果。这类任务耗时几秒到几分钟，中间没有 ⏳ 时用户会以为消息丢了。⏳ 那条说清在等什么，不承诺时长。有预算的任务（`draw_budget`、`music_budget`、`video_budget`）在发起前判，不跑到一半才发现超了。中途被取消时，不把半个状态留在库里。

视频解析的取片是同一类（几十兆下载），但**不预告**：超过 `ack_after_seconds`（默认 20 秒）还没完才补一句 ⏳。它的动作由链接本身触发，用户没在等一次「提交」，多数取片在这个点之前就完了，少发一条是一条。

### 8. 额度与冷却

| 位置 | 键 | 语义 |
| --- | --- | --- |
| 复读机 | `cooldown_seconds` | 同一句接力后的静默期 |
| 搭话 | `cooldown_seconds` / `max_per_hour` | 全局冷却与每小时上限 |
| 搭话 | `search_budget` | 每轮可用的联网查询次数 |
| 搭话 | `draw_budget` / `music_budget` / `video_budget` | 每轮可用的生成次数，0 即关闭 |
| 资讯 | `realtime_max_per_hour` | 实时快报的每小时上限 |

后缀的完整口径见[总纲第四节第 9 条](GUIDELINES.md#9-限流与冷却)。

额度用完时说清什么时候恢复，并给一条此刻仍然能做的事。花钱的能力默认克制：音乐一次约 $0.5，视频一次约 $1.2，所以默认额度是 1，高峰归零。额度为 0 时工具不进白名单，提示词里也不提。

### 9. 破坏性操作

| 操作 | 门槛 |
| --- | --- |
| 改插件开关与配置 | `[ctl].admins`，且保留 `ctl` 自己的管理入口 |
| 移除自己的管理权限 | 拒绝，并给出另一条路（换人或停机改配置） |
| 手动 `/restart` | 仅管理员，且 `allow_manual_restart = true` 已开 |
| 清空智能体（`-*` / `-*!`） | 认管理员 |
| 群管理（踢人、禁言、改名、精华） | `[ambient].management_groups` 里显式列出的群 |
| 撤回 | 只撤回机器人自己或明确引用到的消息 |

被拒时要说出门槛：「此操作仅限 ctl.admins 中的全局管理员；请由本机维护者在 config.toml 的 `[ctl]` 中配置 `admins = [QQ号]`」。用户读完知道该找谁、该改哪个键。只回一句「无权限」不含下一步。

### 10. 先不让错

先让错误出不来，再谈错误文案。把非法输入变得打不出来：参数写进占位符（`裁剪 <行>x<列>`），固定取值用斜杠列出来（`ai实时模式 <精选|全部>`）。把范围写在问句里：「最多 7 字且不能包含指令符号」比事后报一句「名称不合法」有用，直接作为 `group_title` 的说明。给破坏性操作加门槛，见上一节。

三样都用尽之后才轮到错误消息，那时它的任务是说清发生了什么，并给出下一步。

## 四、节奏

在群聊里，动效就是消息的时序。没有补间动画，能调的是下一条什么时候出现，以及一件事拆成几条说。M3 的动效时长以毫秒计，这里的单位是「一条消息」：

| 档 | 时长 | 用在 | ayjx 的取值 |
| --- | --- | --- | --- |
| 不停顿 | 0 | 同一件事的内容，不拆条 | 指令回执与结果同一条 |
| 短 | 0.3–1 s | 同一动作的两段之间 | `send_freshness_seconds` 内的合并 |
| 中 | 1–3 s | 长内容断句，让人来得及读 | 搭话的 `breath::split` 按条发出 |
| 长 | 数十秒到数分钟 | 等人的窗口、长任务 | `reply_timeout_seconds`、`max_pending_seconds` |

停顿只为让人读完。一句话拆成三条发，是因为它本来就有三件事。等待窗口显示剩余时间或状态，「请稍等」不含信息。节奏要能关掉：`image_enabled`、`plain_text_max_chars`、`[ambient]` 的一整组节奏参数、`stats` 的排期开关都是这一类。逐条揭示对读屏用户是连续打断，对网络差的人是空白。

## 五、自适应与降级

同一条内容要在三层容器里都成立，越往下越朴素，信息不减少：

```text
图片卡片     信息最全、排版最好        需要 Chromium 与 CJK 字体
富文本       合并转发、@、引用、图文混排 需要实现端支持（satori-qq 有）
纯文本       一定送得到                 永远可用
```

从下往上设计：先把纯文本那一层写成完整可用的，再往上叠图。`help`、`ctl` 与卡片的内容与图一致，不会出现图里一套、文字另一套。

降级自动且安静。浏览器缺失、初始化失败、截图超时、尺寸超限、合并转发失败，都不变成一条给用户看的报错：用户没有做错任何事，只该看到结果照常到达，日志里留一行即可。三个触发降级的现实原因：部署者主动关图、本机没有 Chromium、截图超时或超过高度上限（16000 CSS px）与像素预算（6400 万）。

尺寸上守一条：图片按内容定高，宽度固定（卡片为 720 CSS px）。QQ 客户端会把过宽的图缩到看不清，竖向滚动不占额外代价。

## 六、信息架构

ayjx 不用 `插件名.动作` 的形式，用扁平的中文指令加 `/` 前缀：`/撤回`、`/转链接`、`/画像`、`/ai资讯`、`/ctl list`。判据是在群里打出来是否自然，群聊里没有补全与层级导航，多一级就是多一次记忆。

命名有四种成体系的写法：单个动词（`撤回`、`转链接`、`收`）；插件名前缀加动作（`gif变速`、`ai资讯`）；范围加时间加类型（`本群今日发言排行榜`）；符号指令（`##<名称>`、`~<名称> <内容>`、`/#`），用于 oai 的房间管理。

同一个概念在全部插件里只有一个词：

| 概念 | 用 | 不用 |
| --- | --- | --- |
| 插件开关 | `开` / `关` | 启用 / 停用 / 打开 / 关闭 |
| 榜与趋势 | `排行榜` / `走势` | 榜 / 排名 / 榜单 / 趋势 |
| 枚举 | `列表` | 清单 / 全部 / ls |
| 时间切片 | `今日` / `昨日` / `本周` / `上周` / `近7天` / `近30天` / `本月` / `上月` / `今年` / `去年` / `总` | 今天 / 昨天 / 本星期 / 最近一周 … |
| 范围切片 | `本群` / `跨群` / `我的` / `所有群` | 当前群 / 全群 / 个人 / 全部群 |

指令本体里数字紧贴中文（`近7天`），因为要能照打；散文里数字与中文之间留空格（`近 7 天`）。这是唯一一处指令与正文写法不同的地方。

子指令还是参数，看它会不会被单独使用。会则单独一条（`转链接`、`转图片`、`转视频`），不会则用参数（`裁剪 3x3`、`画像 <QQ号>`）。

别名用 ` / ` 在一条记录里并列，渲染时首个抬为主指令（`help / 帮助 / 插件列表`、`转链接 / 看链接 / 提取地址 / url`）。不为兼容保留已废弃的名字，留下旧名会让帮助列表里同时出现两个名字。

「这是什么」在 `/help <插件名>` 的卡片里，「这能做什么」在同上的指令表里，「现在开着吗」在 `/help` 总览与 `/ctl list` 里，「现在配置是什么」在 `/ctl show <插件> [路径]`，「和默认差在哪」在 `/ctl diff <插件>`，「怎么改」在 `/ctl` 的用法页。这六件事都不写进聊天正文，正文里的说明只留一句「下一步做什么」。

## 七、落地检查清单

新增或改动一处交互时逐条过：

- [ ] 这条消息离开上下文还读得懂吗，超过三句了吗
- [ ] 有等待吗，它有自己的终点吗，超时谁来收场
- [ ] 需要指定对象吗，是不是该用引用，有效期说了吗
- [ ] 有并发写入吗，串行化了吗，拿不到时回了 ⏳ 吗
- [ ] 有图吗，渲染不可用时的文本回退信息等价吗
- [ ] 有长任务吗，先回了 ⏳ 吗，取消时状态清干净了吗
- [ ] 花钱吗，额度在发起前判了吗，0 能关掉吗
- [ ] 是破坏性操作吗，门槛说了吗，被拒时给出该找谁了吗
- [ ] 有限流吗，说了什么时候恢复、给了此刻能做的事吗
- [ ] 要求用户回忆什么了吗，能不能改成把选项摆到眼前
- [ ] 加了停顿吗，是为了让人读完，还是只为戏剧效果
- [ ] 没数据时说的是「这里现在是空的」，还是被包成了一句「生成失败」
