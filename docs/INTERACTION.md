## 零、群聊不是 App

把 App 的假设逐条拿掉，剩下的就是这个场所的真实约束：

| App 里有 | QQ 群里 | 由此推出 |
| --- | --- | --- |
| 返回键、导航栈 | 没有。只有一条往下滚的时间线 | 每条消息都要自带上下文，不能依赖“上一屏” |
| 模态对话框 | 没有。追问只是又一条消息 | 追问不能单方面占住别人的下一句话 |
| 悬停、长按、右键 | 没有。只有“发一条消息” | 所有功能都要能用一行文字触达 |
| 当前页面 | 没有。上下文随时被别人的消息冲走 | 状态要能随时重新调出来 |
| 私有画布 | **没有。全体成员都被迫看见机器人的每一条输出** | 刷屏是侵占公共空间，不是小毛病 |
| 应用内设置页 | 没有。配置在 `config.toml` / `/ctl` 里，一般人看不到 | 行为要能从消息本身推断，不能要求先读文档 |
| 稳定的网络与后台 | 没有。进程会被 ColorOS 清理器杀掉，浏览器会缺 | 长任务要能中断、能被重新发起，降级要安静 |

**这些插件不是 App，是群聊里的一位参与者。** 照搬 App 的交互会做出一个
在群里格格不入的东西——长得再像 M3 也没用。

## 一、Think Human：八条原则的译法

依据是 Apple HIG 的八条设计原则。左栏是原话，右栏是它在 ayjx 里的具体含义。

| 原则 | Apple 的一句话 | 在 ayjx 里意味着 |
| --- | --- | --- |
| **Purpose** 目的 | Make something meaningful. | 一个插件只做一件事。`webshot` 不做视频解析，`stats` 不做词云——链接的准入判据是 `video_parse::is_video_link` 一处，两边不各截一次又取一次。 |
| **Agency** 自主 | Let people do things their own way. | 出图能关（`image_enabled`）、插件的开关与配置能改、`ai_news` 的推送目标能逐个增删、`ambient` 的搭话能在群里关。**不把人锁在流程里。** |
| **Responsibility** 责任 | Act in people's best interest. | 破坏性操作有门槛（`[ctl].admins`、`allow_manual_restart`、`[ambient].management_groups`）；花钱的能力有额度（`music_budget` / `video_budget` / `draw_budget`，0 就是关掉）；撤回失败只记日志，不打扰用户。 |
| **Familiarity** 熟悉 | Build on what people know. | 用群里既有的动作——**@、引用、撤回、发一条消息**。ayjx 的追问全靠引用，不发明新仪式。 |
| **Flexibility** 弹性 | Adapt to diverse contexts and needs. | 浏览器不可用或超时 → 卡片退回等价的纯文本；合并转发失败 → 发普通消息；`video_parse` 取不到原片 → 保留预览与直链。 |
| **Simplicity** 简约 | Be clear and direct. | 一条消息至多三句（`CONTENT.md` 3.3）；短反馈不出图；帮助列表条目只给一句话，细节进卡片。**Simplicity 不是极简**——该给的信息不能省。 |
| **Craft** 工艺 | Care about every detail. | 数字两侧的空格、「@」后面那个空格补不补、`[face:277]` 会不会漏成原文、并发时那把锁。**发出去了不算完。** |
| **Delight** 愉悦 | Make it human. | 高光时刻给一次；`CONTENT.md` 把感叹号的口子只留给了真正的庆祝。Apple 同一段里紧接着说：**Don't mistake delight for decoration.** |

最后一条和 `CONTENT.md` 的「克制」是同一件事的两种说法。Apple 的原话值得抄下来，
因为它正好堵住了滥用的口子：

> Keep in mind that people are trying to accomplish a task, so don't let pursuit of
> delight for its own sake get in the way of your product's core purpose.

## 二、四条硬规则

**1. 一条消息说清一件事，超过三句就出图。**
群聊是共享的，多刷一行是所有人替你付的代价。判据是 `CONTENT.md` 3.3
（一条消息至多三句），出路是卡片或帮助页。

**2. 任何等待都要有自己的终点。**
不看「机器人还在跑」，看**用户怎么知道它结束了**：
定时推送有排期与`/ai推送状态`；卡片提取有 30 天的有效期；
模型请求有 `reply_timeout_seconds`；搭话有 `max_wait_seconds`。
没有一个状态可以无限期悬着。

**3. 状态要能重新调出来。**
上下文被冲走是常态，不是异常。
`/ai推送状态` 能问当前目标的所有参数、`/ctl list` 能问全部插件、
`/help <插件>` 能问指令表——凡是「上一次它说了什么」，都要有一条指令能再问一次。

**4. 认得出，而不是记得住。**
群里没有一块地方能长期摆着指令表。指望用户记住 `--` 后面那个开关怎么拼，
不如在他需要的那一刻把选项摆到眼前：参数占位写成 `<必填>` / `[可选]`，
限流被拒时把「怎么恢复」一起说了，帮助卡的页脚给一条能立刻执行的指令。
**凡是要求用户回忆的地方，都是一处设计欠账。**

## 三、交互模式

### 1. 前缀与符号指令

指令前缀 `/` 由 `command_prefix` 配置，默认 `/`。注册表里只写指令本体，
渲染时由框架拼上；符号指令（`/#`、`##`、`~名`、`-#`、`~#`、`~=`、`-*`、`画·<预设>`）
自带写法，不再拼前缀。

**写进正文的指令必须带上当前前缀，且能整条抄走。**
不要硬编码 `/ctl`——部署者可以把前缀改掉，那句提示就成了死路
（`CONTENT.md` 3.4）。

### 2. 后缀驱动的房间设置 —— oai 的语法

`oai` 的房间用**在被操作对象后面追加符号**的方式表达，不另立指令：

```text
房间%模型        换这间房的模型
房间$<提示词>    改这间房的提示词
房间?            联网开关换一边
房间?开 / 房间?关 明确指定；房间?默认 交回全局
```

**这是 ayjx 里唯一一套「对象 + 后缀」的语法，只在 oai 房间内成立。**
要加新的房间设置就沿用这套符号，不要为一个开关再造一条新指令——
同一个动作有两种写法，用户只会记住自己先遇到的那一种。

### 3. 引用即上下文 —— 招牌模式

**ayjx 不用「等你下一句话」这种模态。** 需要指定对象时，一律用**引用**把上下文钉住：

```text
引用一条消息 + 撤回            → 撤回它
引用一条含图的消息 + 转链接      → 提取直链
引用视频站的预览 + 视频         → 取原片进群
引用一张表情 + 收 / 偷 / 存表情  → 收藏它
引用资讯卡片 + 0 或 2 / 1,3-5   → 提取对应链接（无需前缀）
```

这是全套设计里最“native”的一处，它同时解决了三件事：

- **不占住任何人的下一句话。** 引用是显式指定的，所以不存在「悬念」和「悬空」——
  `ai_news` 的提取靠消息号而不是「下一条」，用户可以不回，也可以过两周再回。
- **自带上下文。** 时间线被冲走无所谓，引用本身把「对哪条动手」带过来了。
- **失败可解释。** 没有引用段时能明确回一句「请引用一条……」，而不是沉默。

两条配套约束：

- **必须给有效期。** 引用指向的是历史消息，得说清它还能用多久——
  `ai_news` 的卡片提取限「近 30 天发送的」，超出就明说找不到。
- **不要顺手吞掉普通消息。** 只在「确有引用段、且文本形状对得上」时才响应，
  其余一律放行。宁可漏接，不可误吞。

### 4. 出图的降级路径不是追问

卡片图在群里是**缩略图式**的：读者第一眼看到的是版式，不是正文。
所以「引用卡片 + 回序号」不是多此一举，它是**把图当目录、把文本当正文**的分工——
图上放得下的信息保持好看，放不下的（链接、完整摘要）留在按需提取里。

**图是增强，不是前提。** 出图那条路要有等价文本兜底（见第五节）。

### 5. 并发与串行化

群消息很密（实测约 1.1 万条/天，峰值 1.5 条/秒），两个人在同一毫秒发同一条指令是常态。

凡是「读状态 → 算 → 写状态」的动作，都要串行化。
拿不到的时候**不要静默丢弃**，回一句 ⏳ 说明发生了什么——
静默丢弃会让人以为机器人死了，然后重发，然后更糟。

出图是这里唯一的排队处：`render::web::shoot` 的闸门（3）与 `webshot` 自己的闸门（2）
按「一类工作」分两道，**闸门在 45 秒超时之外获取**，排在后头的请求不会因为前面那张慢
而被判超时。加新的出图调用点不要自己写第二条队列。

### 6. 长任务：先说在做，做完再说一句

生成类任务（画图、写歌、拍片、翻页截图、出画像）都要**先回一条 ⏳**，
再在完成时回结果。理由很直接：这类任务几秒到几分钟不等，中间没有 ⏳，
用户会以为消息丢了。

- ⏳ 那条要说清**在等什么**，不承诺时长（`CONTENT.md` 第二节）。
- 有预算的任务（`draw_budget` / `music_budget` / `video_budget`）在**发起前**判，
  不要跑完才发现超了。
- 中途被取消（进程重启、QQ 掉线）时，不要让任务带着半个状态留在库里。

### 7. 额度与冷却

| 位置 | 键 | 语义 |
| --- | --- | --- |
| 复读机 | `cooldown_seconds` | 同一句接力后的静默期 |
| 搭话 | `cooldown_seconds` / `max_per_hour` | 全局冷却与每小时上限 |
| 搭话 | `lookup_budget` / `search_budget` | 每轮可用的查询次数 |
| 搭话 | `draw_budget` / `music_budget` / `video_budget` | 每轮可用的生成次数，0 即关闭 |
| 资讯 | `realtime_max_per_hour` | 实时快报的每小时上限 |

后缀的完整口径见 [总纲第四节第 9 条](GUIDELINES.md#9-限流与冷却)。

**额度用完时说清什么时候回来**，并给一条此刻仍然能做的事。
死路一条的限流是最伤人的那种——这既是 Agency 也是文案规范里的「永远给下一步」。

**花钱的能力默认要克制。** 音乐一次约 $0.5、视频一次约 $1.2，
所以它们默认额度是 1，高峰归零，且额度为 0 时工具进不去白名单、
提示词里也不提——**不要给一个用不上的工具做广告**。

### 8. 破坏性操作

| 操作 | 门槛 |
| --- | --- |
| 改插件开关与配置 | `[ctl].admins`，且保留 `ctl` 自己的管理入口 |
| 移除自己的管理权限 | 拒掉，并给出另一条路（换人或停机改配置） |
| 手动 `/restart` | 仅管理员，且 `allow_manual_restart = true` 已开 |
| 清空智能体（`-*` / `-*!`） | 认管理员 |
| 群管理（踢人、禁言、改名、精华） | `[ambient].management_groups` 里显式列出的群 |
| 撤回 | 只撤回机器人自己或明确引用到的消息 |

被拒的时候要把门槛说出来：「此操作仅限 ctl.admins 中的全局管理员；请由本机维护者
在 config.toml 的 `[ctl]` 中配置 `admins = [QQ号]`」——用户读完知道该找谁、该改哪个键。
**只说「无权限」不算拒绝一次，只算把问题丢回去了。**

### 9. 先不让错，再谈报错

错误文案写得再好，也不如一开始就没法出错。三种手段，按优先级排：

**把非法输入变得打不出来。** 参数写进占位符（`裁剪 <行>x<列>`），
固定取值用斜杠列出来（`ai实时模式 <精选|全部>`），用户照着抄就不会错。

**把范围写在问句里。** 「最多 7 字且不能包含指令符号」比事后报一句
「名称不合法」有用得多——不如把这条直接作为 `group_title` 的说明。

**把破坏性操作挡在门后。** 见第 8 条。

只有这三样都用尽了，才轮到错误消息出场——而那时它的任务只剩一件：
**说清发生了什么，并给出下一步。**

## 四、节奏

在群聊里，动效就是消息的时序。没有补间动画可做，唯一能调的是
「下一条什么时候出现」，以及「一件事拆成几条说」。

M3 的动效时长以毫秒计，因为它动的是像素；这里的单位是「一条消息」，
量级整整大一档：

| 档 | 时长 | 用在 | ayjx 的取值 |
| --- | --- | --- | --- |
| 不停顿 | 0 | 同一件事的内容，不拆条 | 指令回执与结果同一条 |
| 短 | 0.3–1 s | 同一动作的两段之间 | `send_freshness_seconds` 内的合并 |
| 中 | 1–3 s | 长内容断句，让人来得及读 | 搭话的 `breath::split` 按条发出 |
| 长 | 数十秒到数分钟 | 等人的窗口、长任务 | `reply_timeout_seconds`、`max_wait_seconds` |

三条规则：

**停顿只为让人读完，不为制造悬念。** 一句话拆成三条发，是因为它本来就有三件事；
把它拆开只为显得「有节奏」是错的。

**等待窗口必须显示剩余时间或状态。** 「请稍等」不是节奏，是失联。

**节奏要能关掉。** `image_enabled`、`plain_text_max_chars`、
`[ambient]` 的一整组节奏参数、`stats` 的排期开关——凡是靠时序做的表达，
都要留一个「一次说完」或「干脆不说」的开关。逐条揭示对读屏用户是连续打断，
对网络差的人是漫长的空白。

## 五、自适应与降级

同一条内容要在三层容器里都成立，越往下越朴素，但**信息一样不能少**：

```text
图片卡片     信息最全、排版最好        需要 Chromium 与 CJK 字体
富文本       合并转发、@、引用、图文混排 需要实现端支持（satori-qq 有）
纯文本       一定送得到                 永远可用
```

**从下往上设计，不是从上往下裁。** 先把纯文本那一层写成完整可用的，
再往上叠图；而不是先做图，再想图挂了怎么办。`help` / `ctl` 与卡片
「内容与图一致，绝不出现图里一套、文字另一套」就是这么来的。

**降级要自动且安静**：浏览器缺失、初始化失败、截图超时、尺寸超限、
合并转发失败——都不该变成一条给用户看的报错。**他没做错任何事**，
只该看到结果照常到达，最多在日志里留一行。

三个触发降级的现实原因：部署者主动关图（`image_enabled = false`）、
本机没有 Chromium、截图超时或超过高度上限（16000 CSS px）与像素预算（6400 万）。

尺寸上只需守一条：**图片按内容定高，宽度固定**（卡片为 720 CSS px）。
QQ 客户端会把过宽的图缩到看不清，而竖向滚动是免费的。

## 六、信息架构

### 指令树

ayjx 不用 `插件名.动作` 的形式，而是**扁平的中文指令 + `/` 前缀**：
`/撤回`、`/转链接`、`/画像`、`/ai资讯`、`/ctl list`。

**判据是「在群里打出来自不自然」，不是「归类整不整齐」。**
群聊里没有补全与层级导航，多一级就是多一次记忆。

命名有四种成体系的写法，各自有适用面：

| 写法 | 例 | 用在哪 |
| --- | --- | --- |
| 单个动词 | `撤回`、`转链接`、`收` | 一句话能说完的动作 |
| 插件名前缀 + 动作 | `gif变速`、`ai资讯`、`ai推送添加` | 同族指令多、需要一眼看出归属 |
| 范围 + 时间 + 类型 | `本群今日发言排行榜` | 参数天然成组，直接读出来比记参数省事 |
| 符号指令 | `##<名称>`、`~<名称> <内容>`、`/#` | oai 的房间管理，短且高频 |

**同一个概念在全部插件里只有一个词。** 已经统一的：

| 概念 | 用 | 不用 |
| --- | --- | --- |
| 插件开关 | `开` / `关` | 启用 / 停用 / 打开 / 关闭 |
| 榜与趋势 | `排行榜` / `走势` | 榜 / 排名 / 榜单 / 趋势 |
| 枚举 | `列表` | 清单 / 全部 / ls |
| 时间切片 | `今日` / `昨日` / `本周` / `上周` / `近7天` / `近30天` / `本月` / `上月` / `今年` / `去年` / `总` | 今天 / 昨天 / 本星期 / 最近一周 … |
| 范围切片 | `本群` / `跨群` / `我的` / `所有群` | 当前群 / 全群 / 个人 / 全部群 |

**指令本体里数字紧贴中文（`近7天`），因为要能照打；散文里数字与中文之间留空格
（`近 7 天`）。** 这条是唯一一处「指令与正文写法不同」，别统一掉。

### 子指令还是参数

| 用另一条指令 | 用参数 |
| --- | --- |
| 是**另一件事** | 是同一件事的**另一种口径** |
| `转链接` / `转图片` / `转视频` | `裁剪 3x3`、`画像 <QQ号>` |
| 用户会单独记住它 | 用户只在需要时才附上 |

判据：**它会不会独立出现在你对朋友的推荐里。** 会——单独一条；不会——参数。

### 别名

`help / 帮助 / 插件列表`、`转链接 / 看链接 / 提取地址 / url`、
`裁剪 / 切图 / 分割`——**同一条记录里用 ` / ` 并列**，
渲染时首个抬为主指令，其余降级为别名。

别名是给「先遇到过旧写法」的人用的。**不要为兼容再留一个已废弃的名字**：
留下来就等于把历史包袱又搬一遍，而且帮助列表里会同时出现两个名字，反而更难学。

### 说明的位置

| 问题 | 答案在哪 |
| --- | --- |
| 这是什么 | `/help <插件名>` 的卡片（`summary` 与 `display_name`） |
| 这能做什么 | 同上的指令表 |
| 现在开着吗 | `/help` 总览、`/ctl list` |
| 现在配置是什么 | `/ctl show <插件> [路径]` |
| 和默认差在哪 | `/ctl diff <插件>` |
| 怎么改 | `/ctl` 的用法页 |

**这六件事都不要写进聊天正文。** 正文里的说明只留一句「下一步做什么」。

## 七、落地检查清单

新增或改动一处交互时，逐条过：

- [ ] 这条消息离开上下文还读得懂吗（时间线会被冲走）
- [ ] 超过三句了吗；超了的部分该出图吗
- [ ] 有等待吗——它有自己的终点吗，超时谁来收场
- [ ] 需要指定对象吗——是不是该用引用，而不是「等你下一句话」
- [ ] 引用的有效期说了吗
- [ ] 有并发写入吗——串行化了吗，拿不到时回了 ⏳ 吗
- [ ] 有图吗——渲染不可用时的文本回退信息等价吗
- [ ] 有长任务吗——先回了 ⏳ 吗，取消时状态清干净了吗
- [ ] 花钱吗——额度在发起前判了吗，0 能关掉吗
- [ ] 是破坏性操作吗——门槛说了吗，被拒时给出该找谁了吗
- [ ] 有限流吗——说了什么时候回来、给了此刻能做的事吗
- [ ] 文案里的指令带当前前缀了吗，能整条抄走吗
- [ ] 要求用户回忆什么了吗——能不能改成把选项摆到眼前
- [ ] 能不让它出错吗——占位符代替拼写、范围写进问句、门槛挡住破坏性操作
- [ ] 加了停顿吗——是为了让人读完，还是只为戏剧效果
- [ ] 纯文本那一层单独拿出来还成立吗

---

这份规范的判断依据来自 Apple Human Interface Guidelines 的八条设计原则，
可用性部分参考了 Nielsen Norman Group 的启发式评估，无障碍部分依据 WCAG 2.2。
三者都不是照搬——它们为桌面与网页而写，这里逐条译成了群聊这个媒介里的具体动作。
