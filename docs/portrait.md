# 用户画像

读一个群成员的历史发言，写一份侧写报告，出一张图文卡片。指令是 `画像`。

报告不是数据汇总，是一段判断。它会说出本人未必愿意承认的事，所以笔法是白描的、
克制的，不奉承也不羞辱。

## 用法

| 指令 | 说明 |
| --- | --- |
| `/画像` | 查看自己的画像 |
| `/用户画像` / `/我的画像` | 同上 |
| `/画像 @某人` | 查看对方的画像 |
| `/画像 <QQ号>` | 按 QQ 号查看 |

关键词之后只允许空白、`@`、一串数字，或者「报告」两个字，其余一律不算指令。日常闲聊里说到「画像」这个词不会触发模型调用。消息里 @ 机器人自己不算目标，会退回成查自己。

## 报告的结构

| 区块 | 内容 |
| --- | --- |
| 代号与题记 | 2—7 字的代号，加一句结论式的题记 |
| 总评 | 三到四句，先给判断再给依据 |
| 读数 | 发言数、活跃天数、跨度、平均字数、最常开口的钟点 |
| 侧写 | 三面，固定是**立身 / 心相 / 人群** |
| 签 | 签号、签等、四句签诗、解语 |
| 刻度 | 四个心理维度的分数与依据 |
| 常谈的事 | 反复提到的话题 |
| 他自己的话 | 逐字引用，附挑它的理由 |
| 活跃节律 | 24 小时分布 |
| 赠言 | 收尾的一句话 |

三面侧写是报告的主体：

- **立身**：他怎样对待做事、秩序、体面与成就。看的是他与劳作、规矩、输赢的关系，不下「他做什么工作」的结论。
- **心相**：他的欲望、恐惧、自欺，与他不肯承认的那一部分。
- **人群**：他在人堆里的位置——怎样靠近、怎样退开，拿什么换被需要。

签是每次现抽的，不是固定的吉祥话。中平、中下也可能出现，解语要落回这个人的处境。

## 报告的来源

分成三步。

1. 采集。只读 `message_records`，范围是该用户在群里的发言（`group_id != 0`），并排除 `role = 'self'`。本机机器人与号主共用同一个 QQ 号，记录靠 `role` 区分人和机，不排除就会把机器人自己说的话算到号主头上。统计发言总数、活跃天数、24 小时与星期分布、常在的群、消息类型构成与高频词；发言样本按时间等距抽取，并保证最长的几条入选。
2. 分析。素材交给模型，要求返回一个固定字段的 JSON。引语必须逐字出自样本，比对不上的会被丢掉；三面侧写的键名认不出来时按出现顺序补位，模型给的标签一律不采信。模型调用失败、超时或 JSON 解析失败时，改用统计量拼一份降级画像，报告上会标出「纯统计版」。
3. 出图。HTML 模板截图，版心 720 CSS 像素，正文 19.5—20.5px、行高 1.8—1.92。日读与夜读两套纸色主题，按北京时间 07:00—18:59 自动切换。显示级的文字（代号、签诗、引语、赠言）用衬线，其余用无衬线。报告开头的头像按 QQ 号从 QQ 公开头像 CDN（`q.qlogo.cn`）取回，转成 data URL 内嵌进 HTML；取不到时用名字首字代替。出图失败时退回一份文字版。

每一次生成的 HTML 会写到 `data/portrait/`，保留最近 40 份，可以用来核对版式。

## 数据去向

报告本身不发原始记录，但下面这些内容会发给 `model` 指向的模型接口：

- 统计数字与高频词；
- 最多 `max_samples` 条发言样本，每条截断到 90 字，总量不超过 9000 字；
- 对象的群名片与 QQ 号。

接口地址由 `model` 的供应商前缀决定，见 `[oai.providers]`。提示词明确要求模型不写外貌、性别、年龄、地域、收入、健康与政治立场，也不臆断具体职业、住处与私人关系。

出图之前还会向 `q.qlogo.cn` 请求一次该 QQ 号的头像，只取图，不上传任何内容。

报告页脚写着「仅供娱乐，不作凭据」。它读的是群聊里愿意公开说的那部分，不是本人的全部。

## 配置

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 插件开关 |
| `model` | `deepseek/deepseek-flash` | 分析用的模型，写 `供应商/模型` |
| `thinking` | `high` | 思考强度 `off` / `minimal` / `low` / `medium` / `high` / `xhigh`；留空交给接口默认 |
| `days` | `0` | 只统计最近多少天；0 表示全部留存记录 |
| `max_samples` | `120` | 交给模型的样本条数 |
| `max_scan` | `8000` | 一次最多读多少条原始记录 |
| `theme` | `auto` | `auto` / `light` / `dark` |
| `image_scale` | `3.0` | 出图倍率，1—4 |
| `cooldown_seconds` | `180` | 同一个目标两次生成之间的最短间隔 |
| `channel` | 空 | 群名单，语义同 `[stats.channel]` |

思考强度给到 `high` 是刻意的：侧写要先读完一百多条样本再落笔，调低会让结论退回到
「话多话少、白天黑夜」这一层。

## 频次限制

同一个目标同时只允许一次生成，`cooldown_seconds` 之内不重复。两道闸只拦发指令的人，不影响其它功能。

## 端到端验证

```sh
cargo test --release portrait_live -- --ignored --nocapture
```

它读 `config.toml` 与 `data/bot.db`，跑真模型、出真图，打印收口后的画像与签，
并把出图写到临时目录。目标默认取记录最多的人，也可以用 `PORTRAIT_LIVE_USER=<QQ号>` 指定。
