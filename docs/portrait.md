# 易经画像

读一个群成员的历史发言，用**大衍筮法**为他起一卦，再用这一卦的道理写一份画像，出一张图文卡片。指令是 `画像`。

卦不是模型编的，也不是随机抽的签——他留下的发言与数目就是蓍草。同一个人、同一批素材起出来的是同一卦；他又说了几百句之后，卦才会跟着动。模型只做一件事：把这一卦落在他身上。

报告不是数据汇总，是一篇判断。它会说出本人未必愿意承认的事，所以笔法是白描的、克制的，不奉承也不羞辱。通篇用白话写，不用文言词，不用比喻与格言。

## 用法

| 指令 | 说明 |
| --- | --- |
| `/画像` | 查看自己的画像 |
| `/用户画像` / `/我的画像` / `/易经画像` | 同上 |
| `/算卦` / `/起卦` / `/卜卦` | 同上，卦味的别名 |
| `/画像 @某人` | 查看对方的画像 |
| `/画像 <QQ号>` | 按 QQ 号查看 |

关键词之后只允许空白、`@`、一串数字，或者「报告」两个字，其余一律不算指令。日常闲聊里说到「画像」「算卦」这些词不会触发模型调用。

唯一的例外是消息里带了明确的 `@`：平台会把「@某人的名字」也写进文本段，于是关键词后面常常跟着「黑猫警长」以及他随口的半句话。目标是谁已经写在 `@` 里，这时候不挑剔后面那点尾巴。前缀也可以躲在名字后面——`@小黑 /画像` 与 `/画像 @小黑` 都认。消息里 `@` 机器人自己不算目标，会退回成查自己。

## 起卦

用的是《周易》的大衍筮法，十八变而成一卦：

1. 五十策取一不用，四十九策**分二**，随手分成左右两堆；
2. 右堆取一根**挂一**，挂在指间；
3. 左右各**揲四**，余数为一到四（整除时记四）；
4. **归奇**——两处余数加上挂起的那一根，共五或九（第二、三变是四或八）；
5. 剩下的是四十四或四十。如此**三变**之后余三十六、三十二、二十八或二十四策，除以四得九、八、七、六：
   **九为老阳、八为少阴、七为少阳、六为老阴**。十八变得六爻，自下而上，卦成。

老阳与老阴是**变爻**，把它们翻过来就是**变卦**（易学里叫之卦）。占法按朱熹《易学启蒙》的变占例取，随变爻条数分七种，报告上会写明这一次看哪一爻。

分二的随机来自一个以素材为种子的伪随机源，种子是他自己的指纹：发言条数、起止时间、活跃天数，以及他说过的那些句子。所以卦是「他的」，且可复现——同一批素材，起出来的是同一卦。

## 报告的结构

| 区块 | 内容 |
| --- | --- |
| 代号与题记 | 2—7 字的代号，加一句结论式的题记 |
| 读数 | 发言数、活跃天数、跨度、平均字数、最常开口的钟点 |
| 卦象 | 六爻之象、卦名卦序、上下卦、卦辞与义理，以及起卦的策数、变爻、变卦与看哪一爻 |
| 总评 | 把这一卦与他接上的那一段 |
| 详说 | 四到六段，段落与引语交织——引语落在论证里，不贴到文末 |
| 变化 | 他现在卡在哪一处、往哪儿动 |
| 赠言 | 收尾的一句话 |

没有分点，没有刻度条，没有话题标签。报告是一篇文章，读的是一个人的一件事。

## 卦的义理

六十四卦的卦名、卦辞与义理都编译进二进制（`src/plugins/portrait/divine.rs`）。卦辞是经文原文；义理是这一卦讲的那件道理，用白话写成，例如「屯」是开头就遇上难处、先扎住根再找人，「需」是云在天上雨还没落、该等就等。爻位之义（初爻位置低不宜抢先、二爻位置稳多得助、三爻进退之间最易出错、四爻离主位近易犹疑、五爻是主位看担当、上爻事到头该收）与变占法的说法同样写成白话。

模型拿到的不只是卦名：卦辞、义理、六爻的策数、变爻的爻题与爻位之义，以及变卦的卦辞与义理，一并下发。提示词里定了三条：**卦就是人**（不许拿卦给他贴标签）、**卦说的是变化不是判决**（不许富贵、不许祸福）、**宁少说不空说**（每句都要有出处）。

提示词对文风的要求是硬性的：说今天的话，一句话说一件事，写成完整的陈述句；每一句判断后面要有他说过的话、他在群里做的动作、数字或时间撑着；卦辞爻辞照写之后要紧跟一句白话讲明白，原文只引必要的那一句；不用比喻、对仗、金句与格言体，不用评价词与模糊限定；段末说完事就停，不加总结性的判断；数字一段里至多两三处，只留撑得住判断的；同一件事只说一遍，同一个数字不报两遍。

## 报告的来源

分成四步。

1. 采集。只读 `message_records`，范围是该用户在群里的发言（`group_id != 0`），并排除 `role = 'self'`。本机机器人与号主共用同一个 QQ 号，记录靠 `role` 区分人和机，不排除就会把机器人自己说的话算到号主头上。统计发言总数、活跃天数、24 小时与星期分布、常在的群、消息类型构成与高频词；发言样本按时间等距抽取，并保证最长的几条入选。
2. 起卦。从上面那份素材取指纹作种，走大衍筮法得本卦、变爻与变卦。这一步不花模型的钱，也不依赖接口。
3. 分析。卦与素材交给模型，要求返回一个固定字段的 JSON。引语必须逐字出自样本，比对不上的会被丢掉；段落与引语同列一队，按序渲染。**模型调用失败、超时或 JSON 解析失败时，卦仍然在**——报告上会标出「批语未落」，留下卦象、读数与一句实话。
4. 出图。HTML 模板截图，版心 720 CSS 像素，正文 19.5—20.5px、行高 1.9—2.0。日读与夜读两套纸色主题，按北京时间 07:00—18:59 自动切换。显示级的文字（卦名、爻题、卦辞、代号、批语、引语）用衬线，其余用无衬线。报告开头的头像按 QQ 号从 QQ 公开头像 CDN（`q.qlogo.cn`）取回，转成 data URL 内嵌进 HTML；取不到时用名字首字代替。出图失败时退回一份文字版。

每一次生成的 HTML 会写到 `data/portrait/`，保留最近 40 份，可以用来核对版式。

## 数据去向

报告本身不发原始记录，但下面这些内容会发给 `model` 指向的模型接口：

- 统计数字与高频词；
- 最多 `max_samples` 条发言样本，每条截断到 90 字，总量不超过 9000 字；
- 对象的群名片与 QQ 号；
- 起好的那一卦（卦名、卦辞、义理、策数、变爻、变卦与看哪一爻）。

接口地址由 `model` 的供应商前缀决定，见 `[oai.providers]`。提示词明确要求模型不写外貌、性别、年龄、地域、收入、健康与政治立场，也不臆断具体职业、住处与私人关系。

出图之前还会向 `q.qlogo.cn` 请求一次该 QQ 号的头像，只取图，不上传任何内容。

报告页脚写着「仅供娱乐，不作凭据」。它读的是群聊里愿意公开说的那部分，不是本人的全部。

## 配置

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 插件开关 |
| `model` | `deepseek/deepseek-flash` | 分析用的模型，写 `供应商/模型` |
| `thinking` | `high` | 思考强度 `off` / `minimal` / `low` / `medium` / `high` / `xhigh`；留空交给接口默认 |
| `days` | `0` | 只统计最近多少天；0 表示全部留存记录 |
| `max_samples` | `120` | 交给模型的样本条数 |
| `max_scan` | `8000` | 一次最多读多少条原始记录 |
| `theme` | `auto` | `auto` / `light` / `dark` |
| `image_scale` | `3.0` | 出图倍率，1—4 |
| `cooldown_seconds` | `180` | 同一个目标两次生成之间的最短间隔；这期间再问重发上一次的结果 |
| `channel` | 空 | 群名单，语义同 `[stats.channel]`；**两边都留空就是对所有群生效**，不需要单独开群 |

思考强度给到 `high` 是刻意的：详说要先读完一百多条样本再落笔，调低会让结论退回到「话多话少、白天黑夜」这一层。

注意 `days` 与 `max_samples` 会改变下发的素材，也就改变了种子里的一部分，**卦可能跟着变**。想复现某一卦，就把这两项也固定下来。

## 频次限制

同一个目标同时只允许一次生成；`cooldown_seconds` 之内再问一次，不重新生成，而是把上一次那张卡片（出图失败时是那段文字）原样再发一遍——冷却期里同一批素材起的还是同一卦，为它再掏一次模型与出图的钱没有意义。缓存只留最近问过的那几个人，被挤掉、或者上一次压根没发出东西时，退回一句「刚画过，N 秒后再来」。两道闸只拦发指令的人，不影响其它功能。

## 端到端验证

```sh
cargo test --release portrait_live -- --ignored --nocapture
```

它读 `config.toml` 与 `data/bot.db`，跑真模型、出真图，打印起卦的结果与收口后的画像，
并把出图写到临时目录。目标默认取记录最多的人，也可以用 `PORTRAIT_LIVE_USER=<QQ号>` 指定。

只想看卦起得对不对（不花钱、不联网）：

```sh
cargo test --bin ayjx divine:: -- --nocapture
```
