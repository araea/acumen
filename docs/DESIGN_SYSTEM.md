## 一、主张

> M3E for expression. HIG for experience. Design Tokens for consistency. Platform conventions for adaptation.

四句有先后，与总纲那三句是同一件事的两种写法（总纲的 Built on Material / Behave Native / Think Human 是前四句里的三句）。

Material 3 Expressive 给表现力与系统化的视觉取值。Apple HIG 给清晰、克制、层级与自然交互。Design Tokens 把两者收成同一份数字，落在 `res/cards/m3e.css` 与 `res/console/app.css`。平台惯例决定落地形态。

这不是把两套风格混在一起，也不是模仿某个平台的外观。前三句合起来是一套设计语言，第四句说明这套语言不要求所有媒介长得一样：卡片位图、控制台网页、群聊纯文本是同一套语言的三种形态。

---

## 二、哲学

五组边界。每一组左边是要达到的，右边是不许越过的。

| 要 | 不要 |
| --- | --- |
| 有表现力 | 制造视觉噪声 |
| 简洁 | 因为追求极简而丢信息 |
| 有活力 | 过度娱乐化 |
| 精致 | 依赖无意义的装饰 |
| 流畅 | 动画干扰正在做的事 |

另有一条：统一，但不要求所有元素完全相同。相同语义、相同状态、相同操作一致；重要程度不同、功能不同、交互性质不同的元素可以有不同表现。五张卡片版式各不相同，共用一张纸；控制台与卡片取同一支字阶的两档，不是两套字阶。

---

## 三、视觉语言 · M3 Expressive

视觉这一层借鉴 Material 3 Expressive，取九样：

- 有表现力的色彩
- 语义化的色彩角色
- 清晰的字体层级
- 有表现力的形状
- 有意义的容器
- 明确的视觉重心与层级
- 有意图的对比
- 可随内容调整的构图
- 有表现力的运动

把它简化成「大圆角 + 卡片 + 鲜艳颜色 + 动画」是误读。表现力来自颜色、形状、字体、空间、层级与运动之间有目的的组合，不是任何单独一项拉满。

与 M3 的三处刻意偏离（中文加大字阶、离散字重四档、收窄阴影不透明度）写在 `res/cards/m3e.css` 的文件头，不要当成笔误。

## 四、体验原则 · Apple HIG

这套系统从 Apple HIG 取两层。

一层是体验要达到的质量，即下表。左栏是原则，右栏是它在 ayjx 里的含义。

| 原则 | 在 ayjx 里意味着 |
| --- | --- |
| Clarity 清晰 | 一条消息至多三句，短反馈不出图；卡片上六层文案各放一类信息 |
| Deference 尊重内容 | 成图外围是相纸，装饰不压内容；一张卡上只有一个视觉重心 |
| Hierarchy 层级 | 字阶与六层文案一起定层级；不靠颜色单独区分等级 |
| Depth 深度 | 卡面浮在相纸上，高度停在 level 1；不叠卡片，不用阴影堆层次 |
| Directness 直接 | 引用即上下文；指令名与动作同名（`/撤回` 就是撤回）；动作唯一的链接进来就地取原片，没有第二步 |
| Feedback 反馈 | 长任务先回一条 ⏳；拿不到锁回一句说明情况；降级安静，但日志里留一行 |
| Consistency 一致 | 一个注册表、一个出图入口、一条配置写路径；五张卡是同一张纸；控制台与卡片共用一份令牌 |
| Progressive Disclosure 渐进呈现 | `/help` 概览、`/help <插件>` 指令表、`/ctl show` 与 `/ctl diff` 逐层展开；正文只留下一步 |
| Accessibility 可达 | 三层容器的信息等价、48px 触控区、焦点可见、颜色不作唯一通道、状态图标只有六个 |

另一层是拿不准时偏向谁，即 Apple 2026 年 6 月起 HIG 开头的八条原则（Purpose 到 Delight）。逐条译法在[交互规范第一节](INTERACTION.md#一think-human八条原则的译法)。两层不冲突：九条管做出来的东西达到什么质量，八条管冲突时怎么选。

## 五、令牌

所有视觉实现来自令牌，不在版式里另定数值。现有令牌能表达设计意图就复用。同一种数值在两处出现就是缺陷。只有现有系统表达不了、且具有普遍意义的新需求，才加令牌。

十类令牌在本仓库落在哪里：

| 类别 | 落点 |
| --- | --- |
| Color | `res/cards/m3e.css` §7 配色角色，六套 `scheme-*` 方案 |
| Typography | 同上 §2 字阶；界面另取同一支字阶的第二档，覆盖在 `res/console/app.css` 开头 |
| Shape | 同上 §3 形状 |
| Spacing | 同上 §5 间距 |
| Size | 卡片宽 720 CSS px 固定，高按内容；界面结构尺寸收在 `--zy-*` |
| Elevation | 同上 §4 高度，六档 |
| Border | `outline-variant` 一档；能用容器色差分层就不用描边 |
| Opacity | 状态层：悬停 8%、按下 12%，用 `currentColor` 叠在元素自己的 `::after` 上 |
| Motion | 界面：`--zy-duration-*` 与 `--zy-ease-*`；群聊侧是消息时序，见[交互规范第四节](INTERACTION.md#四节奏) |
| State | 界面：`res/console/app.css` §F 状态；卡片是静态位图，状态用容器色表达 |

分工不能混。系统层说「是什么」，版式层只说「摆在哪儿」。`res/console/app.css` 开头有一条纪律与一条测试（`the_layout_layer_borrows_every_value_from_the_system_layer`）盯着：色值、字号、圆角、阴影的字面量一个都不许出现在版式层。

## 六、颜色

颜色先表达语义与层级，其次才是装饰。角色色有 Primary、Secondary、Tertiary、Surface、Container、Error、Outline 等，取值见 `m3e.css` §7。业务代码不直接依赖具体色值。

| 不做 | 理由 |
| --- | --- |
| 大量硬编码颜色 | 换主题时改不干净 |
| 无意义的渐变 | 不表达层级 |
| 每个模块一套主题色 | 同一个群里并排出现就是两套设计 |
| 只靠颜色表达状态 | 色觉障碍与灰度转发下信息丢失 |
| 为了“高级感”滥用低对比度 | 对比度是可达性，不是审美 |

颜色要能回答四件事：什么最重要、什么可以操作、什么属于同一层级、此刻是什么状态。外来颜色（头像主色、用户自选色）只保留色相，明度与彩度换成系统取值。

---

## 七、字体

Typography 是建立层级的主要工具。size、weight、line-height、tracking、contrast 五样一起用，区分眉标、标题、副标题、小节、条目、页脚六层。

不要只靠颜色区分信息等级。不要出现大量意义接近、参数只差一点的文字样式——那通常是没查字阶就新写了一个。界面与卡片取同一支字阶的两档，第二档在 `app.css`，改哪一处都别串。

---

## 八、形状

Shape 有层级与语义。重要程度不同、功能不同、交互性质不同的元素可以有不同的圆角。允许 rounded、pill / capsule、有表现力的几何、非对称构图，但每一处都要有目的。

容器之间用圆角差分层。不要让所有东西都是同一个圆角矩形。

---

## 九、间距与构图

优先用空间建立关系，不用边框与分割线。

```text
靠得近  →  分到一组
留白   →  层级
大小   →  重要程度
对齐   →  顺序
```

不做 Card 套 Card，不做到处都在的分隔线，不给每个元素套独立容器。群消息里也不画分隔线，分组用 `▍` 与空行。判据只有一条：删掉这个容器之后信息关系还清楚，就删掉它。

---

## 十、组件

组件属于同一套系统，继承同一份 Color、Typography、Shape、Spacing、Motion 与 State。优先复用已有组件，不为某一个页面临时造一个视觉相似、实现独立的组件。

卡片这一层的组件基元收在 `m3e.css` §9，成图外围统一走 `.shot` 一处——改任何一张卡的外围，改那一处，不要在各卡的版式里再写一遍。界面那一层的交互基元（按钮、开关、输入、导航、日志面板）收在 `app.css` §D。

---

## 十一、状态

任何交互元素都要考虑完整状态，不只是默认状态。

| 状态 | 在 ayjx 里怎么表达 |
| --- | --- |
| default | 默认容器色；界面另有状态层 |
| hover / pressed | 界面：悬停 8%、按下 12%，`currentColor` 叠在 `::after`；卡片是位图，没有这两个状态 |
| focused | 界面：可见的焦点环；卡片没有 |
| selected | 容器色加一档，或用圆角差；导航用指示条 |
| disabled | 弱化文字色，不用描边色写字 |
| loading | ⏳ 加一句说清在等什么 |
| success / warning / error | `CONTENT.md` 3.5 那六个图标，各表一种含义 |
| empty | 📭，空不是故障 |

状态之间的变化要清晰、一致、可预期：同一个状态在二十三个插件里是同一种表现。界面上能用容器色表达的就不要另加一套符号。

---

## 十二、动效

界面这一侧，动效只碰 `transform` 与 `opacity`——这两样不触发布局，手机上才不抖。时长与曲线收在 `--zy-duration-*` 与 `--zy-ease-*`。外壳不设 `transform` / `filter` / `backdrop-filter`。

群聊这一侧没有补间动画，动效落在消息的时序上：下一条什么时候出现，一件事拆成几条说。停顿只为让人读完。四档时长见[交互规范第四节](INTERACTION.md#四节奏)。

动效要帮助用户理解发生了什么、来自哪里、影响了什么。不做无意义淡入，不为炫技延长操作时间，不做阻碍连续操作的动画。节奏要能关——`image_enabled`、搭话的一整组节奏参数都是这一类。

---

## 十三、平台适配

设计语言统一，实现尊重媒介与输入方式。同一种语言按 Web、手机、桌面、触摸、鼠标、键盘、大屏、小屏调整具体交互与布局。

在本仓库，适配的对象有四个：**卡片**（静态位图，按群聊缩略图校准字号）、**控制台**（可安装的网页，三档宽度对应底栏、导航轨与抽屉）、**群聊纯文本**（永远可用的一层）、**搭话**（口语，整套在文案规范之外）。四者共用一份令牌与一套原则，形态各不相同。

与 [koishi 工作区](https://github.com/araea/koishi-plugin-guidelines)之间也归这一条：两边的主张、哲学、原则与令牌口径相同，但那边的十六个插件各自发布、只出图与发消息，没有网页界面。**Consistency ≠ identical implementation**：保持的是设计语言，不是把界面做成同一个。

---

## 十四、决策优先级

原则冲突时按这个顺序判断：

```text
Usability               可用性
→ Accessibility         可达性
→ Clarity               清晰
→ Consistency           一致
→ Platform conventions  平台惯例
→ Expressiveness        表现力
→ Decoration            装饰
```

视觉表现力不能以牺牲可用性为代价。

本仓库已声明在规范之外的几处，就是这张表在起作用：搭话人格让位给“群里一个普通成员”的口语，日志行里的 `...` 让位给日志的读法，提示词里的分段标记让位给模型的可读性，界面字阶让位给一屏多放几行。让位不等于放宽——机械能验证的条目（术语、图标、标点、配置项描述、锁、开关）没有让位余地，理由一律写在代码注释里。

## 十五、设计之前

动手做任何页面、组件或视觉元素之前，先回答十问：

1. 它解决什么问题？
2. 最重要的信息是什么？
3. 用户首先应该注意到什么？
4. 哪些元素属于同一层级？
5. 哪些信息可以弱化或延后？
6. 有没有现成能复用的令牌或组件？
7. M3E 的表现力体现在哪里？
8. HIG 的清晰、层级、尊重内容与流畅能改善哪一处体验？
9. 符合这个平台与输入方式的习惯吗？
10. 把装饰全部删掉之后，信息结构还成立吗？

先定信息结构，再做视觉。落在代码上时同步三处：文档、`m3e.css` 里对应的组件、各插件的实现。

## 十六、检查清单

- [ ] 取值来自 `m3e.css` / `app.css` 的令牌，版式层没有新写一个相似的数
- [ ] 容器删掉之后信息关系还清楚吗
- [ ] 状态齐了吗：默认、选中、禁用、加载、成功、失败、空
- [ ] 颜色不作唯一通道，第二个通道补了吗
- [ ] 动效只碰 `transform` 与 `opacity`，且能关
- [ ] 界面三档宽度都过了一遍吗
- [ ] 冲突时按决策优先级排过吗
- [ ] 看图：卡片跑 `bash scripts/review-cards.sh`，控制台跑 `bash scripts/review-console.sh`

---

不要机械复制 Material，也不要机械模仿 Apple。从 M3E 拿表现力与视觉系统化，从 HIG 拿清晰、克制、层级与自然交互，最终形成属于知微自己的设计语言。

> M3E for expression. HIG for experience. Design Tokens for consistency. Platform conventions for adaptation.
