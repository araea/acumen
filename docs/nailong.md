# 奶龙提醒

认出群里的奶龙、奶蛙图：只把原图与来龙去脉发到私聊或指定群，由管理员确认后手动处理。**不撤回、不禁言、不在群里说话**——刚上线时，误判的代价比漏掉一张高得多。

默认关闭。打开：`/ctl on nailong`。第一张图到来时自动下载识图模型（约 45 MB，见[模型](#模型)），之后离线运行。

## 提醒

群里有人发图（含动图、QQ 表情商店的动画表情），机器人在后台看，不拖慢别的插件：

1. **认出来** → 原图另存一份、编上号，发到 `notify_targets`。
2. 提醒默认发到号主自己的私聊（QQ 里和自己的那个会话）；也可以写群号或 `private:QQ号`，可以写多个。
3. 提醒长这样：

```text
[原图]
🐉 #12 可能是奶龙图
哈基米酒馆（88083853） · 小明（123456）
模型 87%
本群今天第 3 张；没有自动撤回或禁言，请在群里确认后手动处理。
认错了引用这条回「/奶龙 不是」
```

- **同一群同一个人 `repeat_minutes`（默认 30）分钟内只提醒一次**：期间再发同一类图只记次数（记录里看得到「后又发 N 次」），不再刷消息。
- **全部群每小时最多 `max_per_hour`（默认 30）条**：超出只记录、不再提醒，免得刷屏。
- 群主、管理员与机器人管理员发的图不管（`exempt_staff`）。
- 没认出来什么都不做；不发「正在识别」之类的过程话。

## 改判与翻记录

提醒里有编号，原图与判断依据都在。事后看群、或者根本没看群，都能处理：

- **认错了**：在私聊里引用那条提醒，或在群里引用原图，发 `/奶龙 不是`——记住这类图不提醒，这次标成「已改判不是」。插件没有自动撤过、禁过什么，所以不需要解禁或补话。
- **漏掉了**：引用那张图发 `/奶龙 是`（可写 `/奶龙 是 奶蛙`），往后同类图就提醒。
- **教错了**：引用教过的图发 `/奶龙 忘了`，这张回到模型自己判断。
- **翻记录**：`/奶龙 记录` 列近几天发现的（群里列本群，私聊列全部），带编号、时间、人、依据、有没有提醒、是否已改判；`/奶龙 不是 12` 按编号改判，不必引用；私聊里 `/奶龙 看 12` 再看一遍那张图。

记录与原图存在 `data/nailong/caught/`，留 `keep_days`（默认 7）天，重启不丢。

### 商城表情

QQ 表情商店的动画表情（消息段 `mface`）不带图片地址，只有表情编号。插件按编号到 QQ 的表情资源站取动图（`gxh.vip.qq.com/…/raw300.gif`，取不到再退到 300×300 的 PNG），和普通图片一样抽帧识别。同一个表情编号处处相同，看过一次就按编号记住结论，再有人发连图都不用下。

表情名（如「[奶龙摇摆]」）里写着奶龙、奶蛙的，模型没认出来也算；教过「不是」的照样放过。`check_mface = false` 只看普通图片；指令里引用商城表情测分数、纠正不受这个开关影响。

## 指令

| 指令 | 谁能用 | 作用 |
| --- | --- | --- |
| `/奶龙` | 所有人 | 本群的识别范围、提醒去处、今天发现几张、模型是否就绪 |
| `/奶龙 测` | 所有人 | 引用一张图或商城表情（或附图）看奶龙、奶蛙的分数和会不会提醒 |
| `/奶龙 是 [奶龙\|奶蛙]` | 群主、管理员 | 引用漏掉的图：往后同类图也提醒；不写类别按模型更像的那类 |
| `/奶龙 不是` | 群主、管理员 | 引用误报的图**或私聊里的提醒**：记住这类不提醒，这次标成不是 |
| `/奶龙 忘了` | 群主、管理员 | 引用教过的图：撤销那次纠正，回到模型自己判断 |
| `/奶龙 记录` | 群主、管理员；号主私聊 | 近几天发现的，带编号 |
| `/奶龙 不是 12` | 群主、管理员；号主私聊 | 按编号改判，不必引用 |
| `/奶龙 看 12` | 号主私聊 | 再看一遍那张图 |

号主与 `ctl.admins` 在私聊里也能用上面这些。

教过的图对所有群生效。新图和某张教过的图足够像（余弦相似度 ≥ 0.9）时以教的为准。

教的是**这一张图**，不是让模型变聪明：分类头不会因此重训。实测（20 张不同的奶蛙表情包、图像向量两两比）：同一张图压缩到 q40、裁掉 8% 的边、缩到 1/3、底下加一条字幕、左右翻转，相似度最低 0.93，中位 0.97–1.00，都算同一张；而**两张不同的奶龙图**中位只有 0.57，380 对里没有一对到 0.9。所以群里反复转的那张表情包，误判一次教一次就再也不错；同一套里的别的表情、新冒出来的画风，还得靠模型本身。教过的图多了，可以拿来重训分类头（见[重训](#重训)），发版后所有人的模型一起变好。

## 配置

```toml
[nailong]
enabled = false
targets = ["nailong", "naiwa"]   # 认哪几类
threshold = 0.5                  # 判定阈值 0.3–0.95：高则少误报、多漏报
judge = "auto"                   # auto / local / hybrid / ai，见下文
ai_model = "deepseek/deepseek-flash"
ask_floor = 0.2
sure = 1.0
ai_daily_limit = 300
ai_timeout_seconds = 20
notify_targets = []              # 提醒发到哪：群号或 private:QQ号，可写多个；留空 = 号主私聊
notify_image = true              # 提醒里带原图
repeat_minutes = 30              # 同一人多久内只提醒一次；0 = 每次都提醒
max_per_hour = 30                # 全部群每小时最多几条提醒；0 = 不限
notify_text = "🐉 #{no} 可能是{kind}图\n{group} · {name}（{user}）\n{basis}\n本群今天第 {count} 张；没有自动撤回或禁言，请在群里确认后手动处理。\n认错了引用这条回「{prefix}奶龙 不是」"
exempt_staff = true
ignore_users = []
check_mface = true               # 也看 QQ 表情商店的动画表情
keep_days = 7                    # 发现的图与记录留几天（1–30）
max_images = 4                   # 一条消息最多看几张
max_frames = 4                   # 动图最多抽几帧（均匀抽，第一帧必看）

[nailong.channel]                # 群黑白名单；都空 = 全部群
white = []
black = []
```

占位符：`{no}` `{kind}`（奶龙 / 奶蛙）`{group}` `{name}` `{user}` `{basis}` `{count}` `{prefix}`。文案留空则只发原图；`notify_image` 关掉、文案又留空时，这次只记下不发。

## 认图方式

`judge` 选怎么认：

| 取值 | 做法 |
| --- | --- |
| `auto`（默认） | oai 里配了复核模型（`ai_model`，默认 `deepseek/deepseek-flash`）就按 `hybrid`，没配就按 `local` |
| `hybrid` | 本地模型初筛：分数低于 `ask_floor`（0.2）的直接放过；其余交给多模态大模型确认，它说是才提醒 |
| `local` | 只用本地模型，分数到 `threshold`（0.5）就提醒。离线、免费，误报多一点 |
| `ai` | 每张图都问大模型，用量大，一般用不着 |

复核借 oai 插件的模型配置（`[oai.providers.<供应商>]` 的接口与密钥），oai 插件本身不必开着。问过的图按内容摘要记下结论（`data/nailong/ai_verdicts.json`），同一张图不问第二次；每天最多问 `ai_daily_limit`（300）张。名额用完、超时、出错时这张先放过——本地模型单独判断时误报多，宁可漏一张也不吵错人。`sure` 设成小于 1 时，本地分数到它就不问、直接提醒，能省一点用量。

教过的样本优先于两者；商城表情名字里写着奶龙、奶蛙的直接算，不问。「奶龙 测」会同时列出本地分数与大模型的看法，「奶龙」状态里有今天复核了几张。

实测（2026-10，DeepSeek V4.1 Flash，低推理强度，100 张人工标注图）：皮卡丘、小火龙、小黄人、黄色表情包、群聊截图 50 张一张没认错；奶龙 25 张认出 24；奶蛙 25 张认对 21、另 2 张认成奶龙（照样拦）。一张中位 2.2 秒，约 430 + 340 个 token。按下文留出集，`hybrid` 下群聊图与商城表情只有约 1.4% 需要问大模型。

## 模型

两段：

- **图像编码器**：[MobileCLIP-S0](https://huggingface.co/apple/MobileCLIP-S0) 的视觉部分（[Xenova 转的 ONNX](https://huggingface.co/Xenova/mobileclip_s0)，45 MB），把图压成 512 维向量。从 Hugging Face 下载，失败改走 hf-mirror.com；钉在固定提交，按 SHA-256 校验，存在 `data/nailong/`。权重随 Apple 的研究许可证，只在本机下载使用，不随发布包分发。
- **分类头**：两层小网络（512 → 384 → 3，约 0.8 MB，编进可执行文件），输出「其他 / 奶龙 / 奶蛙」三类概率。

推理用 [tract](https://github.com/sonos/tract)（纯 Rust），不依赖系统里的推理库。手机上一帧约 0.25 秒；同一张图（按内容摘要）再出现直接用上次的结论；同一时间只跑一张，排队超过 12 张时新来的不看，免得刷屏时积压到几分钟后才提醒。

### 为什么不直接用现成的模型

2026-10 调研了公开的奶龙识别实现，在同一批图上实测（MobileCLIP 分类头一栏是留出集：这些来源没有参与训练）：

| 模型（阈值） | 奶龙（XiC1 测试集） | 奶蛙表情包（GeorgeNaNN） | 误判：普通表情包 | 误判：黄色易混图 |
| --- | --- | --- | --- | --- |
| [YOLOX v2.6 tiny](https://github.com/nkxingxh/NailongDetection)（0.5） | 197/235 | 136/145 | **93/533** | 63/352 |
| [YOLOv11n 奶龙](https://github.com/Threkork/kovi-plugin-check-alllong)（0.78） | 174/235 | **50/145** | 2/533 | 2/352 |
| [NaiLongKiller helicopter](https://github.com/SnifferCaptain/NaiLongKiller)（0.5） | 185/235 | 107/145 | 1/533 | 23/352 |
| MobileCLIP-S0 + 分类头（0.8，本插件） | 201/235 | 114/145 | 0/533 | 7/352 |

XiC1 的「奶龙」测试集是搜索引擎抓的，混着不少玫瑰、人像、广告，35 张左右本来就不是奶龙，所以那一栏到不了满分。动图按帧抽查，哪帧像就算。易混图是皮卡丘、小火龙、小黄人、海绵宝宝、黄发角色之类。

现有模型都训练于 2024 年，没见过 2026 年流行的**奶蛙**（AI 生成的写实「变异奶龙」），在奶蛙表情包上只认得出一半左右；YOLOX 版对普通表情包误判太多。所以换成通用图像向量 + 自己训的分类头，并留了「教」的口子：单张图的误判当场纠正，新画风攒够了样本再重训。

### 训练数据（1.10.0 起）

约 7.1 万张去重后的图（8 万帧），人工逐批复核过标签：

| 类别 | 张数 | 来源 |
| --- | --- | --- |
| 奶龙 | 1.4 万 | XiC1/nailong-dataset（含原始抓取目录）、[Hakureirm/NailongKiller](https://huggingface.co/datasets/Hakureirm/NailongKiller) 检测集（有框的）、[refoundd/NailongClassification](https://huggingface.co/datasets/refoundd/NailongClassification)、spawner1145/NailongRecognize 等 GitHub 图库、图片搜索（360、Bing、堆糖）、QQ 表情商城的奶龙官方表情包 |
| 奶蛙 | 0.6 万 | Nailong-Studio/wallpaper、whxoperator/nailongnaiwa、GeorgeNaNN/nailong-memes、各奶蛙桌宠与图标仓库的素材、图片搜索 |
| 其他 | 5.1 万 | 维护者所在群里真实发过的图（截图、照片、表情包，约 1.3 万）、随机抽取的 1500 套 QQ 商城表情、XiC1 的通用表情包与黄色易混图、图片搜索的易混角色（皮卡丘、小火龙、可达鸭、蛋黄哥、小黄人、青蛙、卡皮巴拉……） |

公开数据集的标签相当脏：XiC1「奶龙」测试集 234 张里 39 张不是奶龙或看不清，原始抓取目录与检测集里也夹着人像、商品、别的卡通。清洗流程：模型折外打分，标签与分数冲突的、来源不可靠的（搜索结果、群图），按相似度 0.95 聚簇只看代表，缩略图成批人工过目。群图本身不进仓库，也不分发。

**留出评测**（群图与商城表情一半只测不训，加 XiC1 测试集、GeorgeNaNN 奶蛙表情包；共 1.1 万张，与训练集近乎重复的已剔除）：

| | 奶龙召回 | 奶蛙召回 | 误判（其他被认成） |
| --- | --- | --- | --- |
| 1.9 版分类头（阈值 0.8） | 82.4% | 92.4% | **6.1%**（群图 9.6%） |
| 新分类头，阈值 0.5（`local`） | 100% | 93.6% | 0.20% |
| 新分类头，初筛 0.2（`hybrid` 送复核的） | 100% | 99.4% | 0.55%（再由大模型否掉） |

旧分类头没见过群聊截图，聊天记录、网页、代码、游戏界面能打到 0.99。新分类头的训练加大了少数类权重（样本数反比）、标签平滑 0.05、dropout 0.3、AdamW + OneCycle 40 轮。

换更大的编码器（MobileCLIP-S1/S2）要多花 2–3 倍推理时间；DINOv2、SigLIP2、MobileCLIP-B 在 tract 里跑不起来。`hybrid` 下召回已近满分、误判由大模型兜底，没有换。

### 重训

```sh
python3 scripts/nailong-head.py vision_model.onnx 数据目录 --eval
```

数据目录按 `nailong/`、`naiwa/`、`other/` 分类放图，`test/` 下同样三类是留出集（`--eval` 时只打分）。向量按图片内容缓存，加几张图再训只算新的。脚本写回 `src/plugins/nailong/head.bin`（输入维数、隐藏层宽度写在文件头里，插件照着读），重新构建即可。超参与发布版一致。

### 复核

一次性核对做过即止，不保留专用测试：需要重训时直接跑训练脚本的留出集打分。
