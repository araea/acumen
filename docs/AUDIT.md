# 架构与图片渲染审计

## 结论

保留 Rust / Tokio、Satori、SQLite 与静态插件注册表。注册表是帮助、控制与插件生命周期的共同来源，网页卡片已有统一出图入口。问题集中在任务资源管理与排版边界，不需要整体重写。

## 已修正的问题

| 发现 | 改进 |
| --- | --- |
| 统计图、GIF 信息和拆帧仍同步占用 Tokio 工作线程，其他图片任务直接进入无统一上限的阻塞池 | 统计、词云、GIF、切分统一经过两槽工作池；执行槽由阻塞闭包持有，取消调用方不会突破并发上限 |
| 消息等待 future 被取消后，注册项可能残留；恰好关闭的接收者会吞掉事件 | RAII 注销，发送失败保留原事件并继续匹配 |
| 截图主动关闭过程被取消时，标签页所有权已经取走 | await 完成前保留守卫所有权，取消后仍可清理 |
| 浏览器预热没有启动总时限 | 15 秒超时后继续启动，卡片沿用文本回退 |
| 词云的词绕画布中心摆开，词少时四周是一片暖白，图上就是「白底中间一小团字」 | 改由 araea-wordcloud 在布局层按内容包围盒裁边（`trim` / `trim_margin`），SVG 与 PNG 一致，不再自己解码、扫像素、重编码；成图大小跟着内容走，不会比设定画布还大 |
| GIF 超大缩放、网格、帧数及 NaN 参数缺少护栏 | 256 帧 / 3200 万总像素限制，输出分配前校验尺寸和有限正数 |
| 图片切分向下取整，遗漏右边与底边像素 | 相邻网格边界差分，余数分散到切片；7×5 图片切成 3×2 后能逐像素复原 |
| 稀疏走势图的时间轴按各系列首次出现顺序拼接 | 合并排序；更均匀的纵轴刻度，避免小数刻度取整后重复 |
| Cargo.lock 未纳入版本控制，文档宣称 Rust 1.85 即可构建 | 提交当前通过验证的锁文件，使用 `--locked`；锁定依赖中 SQLx 要求 Rust 1.94，同步最低版本说明 |

两槽工作池限制同时计算的数量，不限制等待中的请求总数。Satori 事件仍异步派发；本次未更改业务消息队列和定时推送策略，也没有把单机测试包装成生产吞吐量基准。外部接口延迟与 QQ 客户端图片压缩不由排版层控制。

## 阅读效果

| 内容 | 调整 |
| --- | --- |
| 帮助、控制 | 标题与状态固定对齐，配置键另起次要一行，避免长键挤压中文名称 |
| AI 资讯、热点、日报、模型榜 | 保留日夜主题，柔化装饰背景，取消标题和正文的 CSS 行数裁切；摘要仍受配置字符预算约束 |
| 用户画像 | 标签 19px、证据 17px，提高次要文字对比度，调整综述行高；保留事实、统计、推断的区分 |
| 智能回复 | 正文 17px，标题层级更清楚，代码块完整换行，表格不再依赖横向滚动，来源标题完整显示 |
| 发言排行榜 | 五个纵列：名次 → 头像 → 色带（实色条 + 淡色轨道）→ 数值 → 占比。名次单列右对齐，前三名走固定的奖牌色（金银铜不跟主题也不跟头像色走）；数值与占比各自右对齐成一列、落在轨道之外的纸上，不再跟着条尾排成阶梯；刻度只留三道，钉在榜首数值的 1/4、1/2、3/4 上，只刻在色带里、与实色条谁盖谁由 `ranking_grid_over_bars` 决定，文字始终在最上层；色带四角圆润，实色条与轨道交界处平切；条内写姓名（放不下即截断）；标题在最上、范围与合计并成一行小字跟随；头像描一圈 outline-variant；每行的条、轨道、数值、占比取自同一支色相的四个调子（头像色先收进固定的饱和度/明度窄带），底淡字深；纸面暖白 |
| 消息类型 | 配色整套换成 `scheme-manual` 的令牌，不再是留在旧配色里的一份 Tailwind 石板灰；分层只用容器色与圆角（相纸 → 卡面 → 卡内轨道三档明度），去掉描边与假投影；名次与排行榜同一套奖牌色，不再跟着类型色变；数值与占比各占一列固定宽度，数值不再随占比的字宽左右晃 |
| 走势 | 纵轴按 `ceil(max/步长)` 定格数，195 画成 0—200 而不是 0—250，折线铺满绘图区；副标题与另外两张图对齐（跨度、合计、出图时间）；峰值标注取这条线的深调；数据点的底圆用纸色而不是纯白；网格与零线取 outline-variant 与 outline 两档。稀疏时间序列仍按日期对齐 |
| 三张图共用 | 图上每一处文字都按 WCAG 2.2 逐对量过对比度（正文 4.5∶1），条色来自头像时按整个色相环扫过；占比一律取整（不足半个百分点写 `<1%`）；暖白纸面与同一套标题层级 |
| 头像取色 | 圆头像四角的透明像素 RGB 是纯黑，从前不看 alpha 一起平均，等于给每张头像掺进两成黑：均色整体压暗，彩度还被稀释掉约三成。改成按 alpha 加权。「读不出色相就退到回退色相」的门槛按本机 142 张真实缓存头像量出来定（中位彩度 0.082，门槛 0.02 影响 12%），不按合成样张定——假头像是一块块纯色，彩度比真头像高一个量级，门槛定高一格线上就会大片退成同一条色。`chart::avatar` 的 `cache_survey` 是重新量的工具，`dump_real_avatar_ranking` 用真缓存出样张 |
| 词云 | 暖白背景、横向排词、低饱和配色；内容外的暖白由库按包围盒裁掉，四周留 4px 碰撞间距 + 8px 纸色边距（出图 2 倍），成图随词量收缩 |
| GIF、切分、媒体、网页截图 | 保留来源内容与原有用途；改善计算调度、尺寸保护和边缘完整性 |

资讯、画像固定 720 CSS px，避免浏览器滚动条把版心压成 705px。网页出图同时等待字体与内嵌图片解码（沿用 900ms 上限）。智能回复卡片加上 CSP，禁止脚本与外部图片加载。本地可信 HTML 清单仍能正常排版。

## 验证与复现

```sh
cargo test --locked
cargo build --release --locked
node tests/foreground.cjs
node tests/restart.cjs
bash scripts/review-cards.sh
```

取色相关的改动另看 `dump_real_avatar_ranking`：它读设备上的头像缓存出一张真实的榜，合成样张看不出取色被推偏。

`review-cards.sh` 只使用合成数据与本地 Chromium，生成帮助 4 张、控制 5 张、资讯 5 张、画像 3 张、智能回复 2 张网页样张，以及 5 张统计图（含 20 人规模的排行榜样张、多系列与单系列两张走势图）与词云。`tests/cards.cjs` 检查出图宽度、横向溢出、高度、脚本拦截、长配置值换行，输出 `layout-audit.json` 与可浏览的 `index.html`。图像的审美仍需实际看图，自动断言只负责结构与内容边界。

生产截图路径另有 ignored 测试，可独立执行：

```sh
cargo test --locked captures_complete_cards -- --ignored --test-threads=1
cargo test --locked renders_a_complete_card -- --ignored --test-threads=1
cargo test --locked oversized_card_fails_without_breaking_the_next_capture -- --ignored --test-threads=1
```
