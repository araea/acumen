# 点歌

群里发 `点歌 <歌名或关键词>`，机器人在 B 站搜一遍、由便宜模型挑一条最贴近的结果，把原片（通常是 MV）发进群。核心是能听到这首歌，成品形态不限。

流程全在幕后：先搜索，再让模型从候选里挑编号。请求里写了歌手名就选那位歌手的版本，没写就优先原唱或官方 MV，翻唱、串烧、教学、纯伴奏都不要。挑选只看标题、UP 主、时长与播放量，走 `[oai.providers]` 里配置的便宜模型。取片与发送复用视频解析的同一条链路，画质、体积上限、超时与 Cookie 都读 `[video_parse]` 的配置。

群里只有成品那一条消息。搜不到、挑不出、取不到都不吭声，原因只写进日志（`Plugin/Song`）；模型超时或回话认不出编号时，退回相关度最高的候选，点歌不能没结果。

## 配置

配置位于 `config.toml` 的 `[song]` 段，完整示例见 [`config.example.toml`](../config.example.toml)。

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `model` | `mimo/mimo-v2.6-flash` | 挑结果用的模型，写 `供应商/模型`，接口取自 `[oai.providers]` |
| `candidates` | `10` | 交给模型的候选上限，取相关度靠前的几条 |
| `max_seconds` | `600` | 成品时长上限（秒），超长的候选直接去掉，几小时的视频进不了群 |
| `timeout_seconds` | `30` | 等模型挑结果的时间上限 |
| `channel.white` | 空 | 非空时只在白名单中的群生效 |
| `channel.black` | 空 | 黑名单中的群不生效，黑名单优先 |

模型挑结果等不到时不会卡住点歌：超时即退回第一条候选。取片侧的并发闸门、临时文件清理与发送兜错全部沿用视频解析（同时最多取两片，气泡在前，成品不带引用与文字）。

## 自检

```sh
# 真搜 B 站与真问一次模型，只打印候选与选择，不发群消息
cargo test --bin acumen song::live -- --ignored --nocapture
```

取片与发送那后半段与视频解析共用实现，那边已有真机用例钉着；要真的听一遍成品，在群里发一句 `点歌 晴天` 就是了。
