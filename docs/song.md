# 点歌

群里发 `点歌 <歌名或关键词>`，机器人在 B 站搜一遍、由便宜模型挑一条最贴近的结果，把原片（通常是 MV）发进群

## 挑选

请求里写了歌手名就选那位歌手的版本，没写就优先原唱或官方 MV，翻唱、串烧、教学、纯伴奏都不要。挑选只看标题、UP 主、时长与播放量，模型取 `[oai.providers]` 里配置的。搜不到、挑不出、取不到都不吭声，原因只写进日志（`Plugin/Song`）；模型超时或回话认不出编号时退回相关度最高的候选。

取片与发送复用视频解析的同一条链路，画质、体积上限、超时与 Cookie 都读 `[video_parse]` 的配置。群里只有成品那一条消息。

## 导出音频

引用一条视频消息发 `导出音频`（别名 `提取音频`），机器人把那条片子的音轨抽出来，作为一个 `.m4a` 音频文件发回群里。不挑来源：机器人取的片、群友发的视频都能导。

流程：取引用消息 → 从 `video` 元素拿到可下载的地址 → 落到本地 → ffmpeg 先试流拷贝，音轨编码进不了 m4a 容器时再重编码一次 → 上传后以群文件发出。这是手动指令：没有引用、引用里没有视频、下载或抽轨失败，都会在群里回一句原因。

体积上限沿用 `[video_parse]` 的 `max_size_mb`，下载与 ffmpeg 各有独立预算，与取片共用同一个并发闸门。临时文件在单次流程结束时就地清理。

## 配置

配置位于 `config.toml` 的 `[song]` 段，完整示例见 [`config.example.toml`](../config.example.toml)。

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `model` | `mimo/mimo-v2.6-flash` | 挑结果用的模型，写 `供应商/模型`，接口取自 `[oai.providers]` |
| `candidates` | `10` | 交给模型的候选上限，取相关度靠前的几条 |
| `max_seconds` | `600` | 成品时长上限（秒），超长的候选直接去掉 |
| `timeout_seconds` | `30` | 等模型挑结果的时间上限；超时即退回第一条候选 |
| `channel.white` | 空 | 非空时只在白名单中的群生效 |
| `channel.black` | 空 | 黑名单中的群不生效，黑名单优先 |

## 自检

# 真搜 B 站与真问一次模型，只打印候选与选择，不发群消息
cargo test --bin acumen song::live -- --ignored --nocapture
